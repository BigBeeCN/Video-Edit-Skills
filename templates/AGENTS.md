# 硬规则（复制进项目根目录的 AGENTS.md，Codex 每次都会读）

> 只放不能违反的规则；流程和参数在 skill 里。若剪辑师本人给出新习惯，以他的为准并更新这里。节奏以 v6 基准为准（B 大确认满意的成片）。本轮流程修订不放宽已认可的 v6 节奏、稳定停留和安全区。

1. 原始素材只读，所有处理在副本上做。
2. 画面上的所有字只能用口播原话（身份标签除外，须标「非原话」）；每条带原话时间戳；用词前核对上下文。听不清的词剪掉，不猜。
3. 气口剪干净，吸气声和废话一点不留。唯一例外：爆点定格，放在自然静音里，≤0.4 秒，全片最多一处。定格不是穿插镜头，不套全屏空镜的 1.6 秒。定格可以选接近闭嘴的帧，那一帧只用于画面，不用来判断说话人。
4. 字幕特效大约每 1–1.3 秒一个，最长间隔约 2.7–3 秒。字效按内容选用，不凑满种类，不把约 44 秒 22 种或 18–22 种当成必达。每种最多 3 次，不连续用同一种。不放宽已认可的稳定停留、安全区和间隔检查。每条 3–4 个爆点，算进总密度。
5. 音效大约 0.4 个/秒（v6 基准 0.387，43.9 秒 17 个）。相邻间隔大约 0.87–4.5 秒，任意 4 秒最多 3 个，不要叠响；预混的复合音效按 1 个计。0.5 个/秒只是上限参考，不是目标。
6. 红色全片只用一次（高潮的章）。
7. 安全区优先：x 90–930、y 200–1540（1080×1920）；大字宽最多 85% 画宽；字不压脸、不压画面里的品牌标识；同屏不超过 3 层。
8. 卡点 ≤2 帧，从“字看得清的第一帧”量。
9. 综合响度 −14 LUFS（±1）。真峰值 ≤ −1 dBTP 只是本项目的交付上限，可以按项目改，不是已核实的抖音官方要求。剪映没有总线限幅。降过总音量之后，必须对最终导出重测综合响度和真峰值，不能凭大约降了 0.5 dB 算通过。
10. 渲染前先把分镜表和重要程度表交用户确认。说话人核对、低清粗剪和低清包装预览是内部检查，不额外再加用户审批。不写未核实的电话、地址。只用确认授权或自行合成的音乐和音效。
11. 质检报告只写亲自核实过的数据，量不到就写“没量到”。不知道的耗时写未知。交出成片不等于用户验收。
12. 先划定说话人、候选句和源片区间，再选句。摄影师画外领读和主人公复述必须分开。选入的人声逐句核对，包括完全被 B-roll 盖住的句子。存疑没关掉不得进入包装。声纹和嘴部开合只是可选辅助；没有可用工具就写明，不能保证自动判断。单帧闭嘴不算换了人。不把某条片子的嘴部或声纹数值写成通用阈值。说话人或转写若做缓存，键里必须同时有源文件身份和源片时间码；对不上就不得沿用。这套缓存未实现。
13. 改了人声、剪点、替换口播或语速之后，相关字幕、字效、音效、B-roll、穿插时长和旧 QC 全部失效，必须重检。局部预览只核改动段和接缝。最终整片导出后仍做完整 QC。不能只重渲孤立几秒就宣布全片正确。低清预览不能代替最终高清细节、综合响度和真峰值。自动缓存、自动失效和增量渲染未实现，不得写成已经支持，也不得写未实测的提速比例。
14. freezedetect 和帧差只定位疑点。帧差大于 0 不能自动判通过，等于 0 不能自动判故障。噪点或字幕动画可能盖住底层口播冻结。人物区域和包装层分开看连续帧，并对照源片、声音和设计意图。完全重复的帧可能是有意定格。模糊或低运动必须复核，不能自动判故障或通过。
15. 每阶段记录开始、结束、主动处理耗时、计算耗时、等待、重跑次数和返修原因。不知道写未知。墙钟跨度不是计算耗时。不承诺交付时长或提速比例。
16. 新片的最终用户验收在用户明确验收之前标待核验。已认可的是 v6 成片的节奏，不自动转到新片。
