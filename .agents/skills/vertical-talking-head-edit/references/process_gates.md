# 流程门（修订草稿）

本页是这一轮的流程修订，供审阅。它不替代 `pacing.md` 里已经认可的 v6 节奏，也不放宽稳定停留、安全区、间隔和音效密度。那些数字仍以 `pacing.md` 为准。

本仓库没有新的说话人程序、缓存程序、增量渲染器或计时器。下面标「待实现」的是要求，不是已有功能。标「待核验」的是还没测完，不是已经通过。

## 状态词

- **已验证**：文档写明的那一次、那一项已经做过。没写进同一句的部分不算。
- **待核验**：还没做，或只做了一部分。
- **待实现**：流程上要有，本仓库没有对应程序。
- **建议**：可以这么做，还不是硬规则。硬规则在 `AGENTS_rules.md`。
- **未知**：没有记录。不猜测，也不用文件修改时间填。

文中旧的「未验证」与「待核验」同一类：还没通过。

## 顺序

素材只读，复制到工作目录后再处理。然后：

1. 素材索引。
2. 转写并人工校对。
3. 划定说话人、候选句、源文件身份、源片时间区间。
4. 选句、定稿、定剪点。
5. 低清口播粗剪，检查说话人、连续嘴型、剪口。
6. 写分镜和重要程度，请用户确认。只此一轮用户确认。
7. 短字效样片。
8. 低清包装预览。
9. 高清输出（成片和/或剪映草稿）。
10. 在最终导出上做 `qc_checklist.md` 的完整 QC。

第 5、7、8 步是内部检查，不另开用户审批。第 6 步的确认保留。存疑人声没关掉，不得写入分镜，也不得进入包装。

低清预览不能代替最终高清成片上的细节，也不能代替综合响度和真峰值。后两项只在最终导出上测。

## 说话人

先有人和候选句，再选句。摄影师画外领读、主人公复述写成不同说话人。选进成片的声音逐句核对，包括成片里会被 B-roll 完全盖住、嘴看不见的句子。那些句子也要听，不能因为画面上没有脸就跳过。

核对表交 `speakers.csv`（UTF-8）：

| 列 | 填什么 |
|---|---|
| 编号 | 稳定 id，如 `spk-04` |
| 说话人 | 画外领读 / 主人公复述 / 其他（写清是谁） |
| 源文件身份 | 见下文「缓存」。不要只写某一台机器的绝对路径 |
| 源片入点_秒 | 该源文件自己的时间轴 |
| 源片出点_秒 | 同上。不用成片时间轴代替 |
| 原话 | 校对后的句子 |
| 被B-roll完全覆盖 | 是 / 否 |
| 选入 | 是 / 否 |
| 存疑 | 是 / 否 |
| 存疑原因 | 没有就写无 |
| 核对 | 通过 / 未关闭 |
| 辅助 | 无 / 声纹 / 嘴部 / 两者。没有工具写「无可用工具，未做自动判断」 |

`核对` 不是「通过」的行，`选入` 必须为否。`存疑` 为是的行，不得进入包装。

声纹和嘴部开合只是可选辅助。本 skill 没有规定可用的自动说话人工具，不能保证自动判断。不设嘴部开合或声纹的通用阈值；某一次制作里的做法和数值留在当次项目，不转抄到本页。

存疑项留在表里，回到源片核对声音、连续嘴型和源片时间区间。闭唇辅音可以只有短暂闭嘴。单帧闭嘴不作为换了说话人的结论。

说话人判断与定格选帧是两件事。定格可以选接近闭嘴的一帧，那一帧不用来识别说话人。

## 预览

不新写渲染器。粗剪和低清都用现有 ffmpeg。字效样片用现有的 HTML/Canvas + Playwright 路径。

- **低清口播粗剪**：用已经定下的入出点，分辨率低于 1080×1920。具体缩放由项目定。本 skill 不规定某一档分辨率，也没有这一步的耗时实测。只看说话人、连续嘴型、剪口。不在这一步加花字、章和定格包装。
- **短字效样片**：先渲染几秒，看字体、描边、入场。样片没看过，不铺全片字效。
- **低清包装预览**：看字幕、关键词是否按 `pacing.md` 停稳、是否压脸、是否进安全区、品牌和隐私是否处理好。标准不因为分辨率低就放宽。

三步都通过，再做高清。低清文件不能拿去交，也不能用来给综合响度或真峰值下通过结论。

项目里已有剪辑师认可的风格模板就沿用。本轮只改「字效按内容选、不凑种类」。这不是一套新的 v6 替代标准。

## 缓存（待实现）

建议缓存：转写、素材索引、稳定中间文件、说话人核对结果。本仓库没有这套缓存，标**待实现**。没有提速实测，提速幅度标**待核验**，不写比例，不承诺更快。

真要做缓存时，转写和说话人结果的键必须同时包含：

- **源文件身份**：能在换机器、换路径之后仍区分是不是同一条素材。只写绝对路径不够。建议用项目内稳定 id，加上文件大小和时长。有内容哈希再放进键里。本 skill 不指定已经在用的哈希算法。
- **源片时间码**：该源文件自己的入点和出点。成片时间轴会随剪辑改变，不能代替源片时间码。

对不上身份或时间码的缓存不得沿用。标过存疑的区间不得沿用。

已可靠的转写，只对存疑区间补识别。「可靠」指：该区间已经人工对照音频校对过，且没有未关闭的存疑。没校对过的全文不算可靠，不能只补一小节就当全文可用。

稳定中间文件只在上游没失效时复用。程序不会自动丢掉旧文件；返修时人按下一节处理。自动失效标**待实现**。

## 失效

自动失效未实现。下面这张表现在就要人工执行。

| 改了什么 | 作废 | 接着做什么 |
|---|---|---|
| 人声或剪点 | 相关字幕、字效、音效、B-roll、时间轴、穿插时长、旧 QC | 局部预览只看改动段和接缝。最终整片导出后做完整 QC |
| 替换口播或改语速 | 同上，包括按旧语速排的穿插时长和旧 QC | 同上 |
| 只改字效外观，时间和声音没变 | 该处安全区、遮挡、与声音的对齐；旧的全片 QC 结论 | 重检该段和接缝。整片导出后仍做完整 QC |
| 剪映里改了时长、变速、空镜或口播 | 改之前的 QC | 对新导出的整片重做 QC。见 `jianying_route.md` |

不能只重渲孤立几秒，就宣布全片正确。接缝指改动段两端相接的画面和声音。旧 QC 报告保留原文件，但标成已失效，不把旧结论抄进新报告。

## 冻帧和响度

冻帧的判据、综合响度和真峰值的测法，以 `qc_checklist.md` 为准。这里只记流程上的两句：

- freezedetect 和帧差只把疑点找出来。人物区域和包装层分开看连续帧，并对照源片、声音、是不是设计上的定格。
- −1 dBTP 是本项目可配置的交付上限，不是已核实的抖音官方要求。降过总音量之后，对这一次最终导出重测综合响度（ebur128 的 I）和真峰值。

## 阶段记录

每个做过的阶段写一行 `stage_log.csv`（UTF-8）。没有自动计时，标**待实现**；表由人填。

| 列 | 填什么 |
|---|---|
| 阶段 | 如抽音频、转写、说话人核对、选句、剪点、低清粗剪、字效样片、低清包装、高清输出、QC、返修 |
| 开始 | 当地时间。不知道写未知 |
| 结束 | 当地时间。不知道写未知 |
| 墙钟跨度 | 开始和结束都知道时，可以相减，并注明这是墙钟。否则写未知 |
| 主动处理耗时 | 人在处理的时间。不知道写未知 |
| 计算耗时 | 程序计算时间。不知道写未知 |
| 等待 | 排队或等候。不知道写未知 |
| 重跑次数 | 数过才填整数。没数过写未知，不要写成 0 |
| 返修原因 | 没有写无。不知道写未知 |
| 备注 | 这一行哪些格子是实测，哪些是未知 |

墙钟跨度含等待，不能抄进「计算耗时」。不从这张表承诺交付时长或提速比例。一次制作的钟点例子在 `case_notes.md`，那是协作者回报，不是本配方的标准工时，不要抄进新项目的表里充当实测。

## 验收和仍待核验

交出成片不等于用户验收。B 大已经满意 v6 成片，并同意节奏按 v6 量。那次认可只针对 v6 的节奏。新片的最终用户验收标**待核验**，直到用户明确验收。

下面这些也不在本轮宣布通过，仍是**待核验**。写流程不必等它们测完：

- 起音 ≤67 ms 的听感。能量口径已验证（29/29，最大 40 ms，降噪压缩后的人声，没有 demucs）。听感、是否吞字头、剪段重跑 ASR，没做。
- 剪映里上下分屏、画中画 / 小窗口的位置。
- 空镜 / B-roll 拖长度、改变速、换成另一条素材。
- 剪映里的音乐闪避关键帧。
- 在剪映里点导出，以及导出成片上的 QC。
- 手绘标记和剪映文字的对齐。

本轮没有在 Windows 上跑剪映，也没有新的导出 QC。
