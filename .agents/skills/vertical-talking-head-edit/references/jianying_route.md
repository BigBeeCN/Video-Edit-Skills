# 剪映工程（pyJianYingDraft）

> 目标：交给剪辑师一份他自己能微调的剪映工程（特效、空镜时长、变速）。剪映 11.7（实测 11.7.0.14652）上已经打开过外部写好的明文草稿。下面「已验证」是这次打开看到的。没测到的仍标「待验证」。剪映里点导出还没测，保底交付仍是成片 + SRT + 分镜表。重要程度表和时长统计表每次都交。

## 已验证（剪映 11.7，人工打开）

- 只生成 `draft_content.json`。素材用绝对路径的这份能打开。只有 `draft_info.json` 的那份也能打开，但剪映在旁边自己写了一份内容相同的 `draft_content.json`，所以它读的是 `draft_content.json`。不要再交 `draft_info.json`。
- 素材路径必须是剪辑师这台机器上的绝对路径。相对路径、以及 `##_draftpath_placeholder_<id>_##` 这种占位符，会整轨显示「媒体丢失」，链接媒体是 0。占位符里的 id 如果和这份草稿的 `draft_id` 不是同一个，同样打不开素材。
- 透明叠加用 ProRes 4444 的 `.mov`，或 PNG 序列。这两样在剪映里是透明的。VP9 `.webm` 在剪映里是全屏黑，不要用。发黑的原因见 `windows_commands.md` 第 6 节：文件里可以有 alpha，剪映不读。
- 字幕写成剪映文本段之后可以改字。关键词分色还在（字体面板里颜色是「多个值」）。
- 口播主轨按段切开之后，常规变速和时长都能改。
- 每条音效在各自的音轨上。
- 草稿里可以带剪映自带特效。这次打开能看到模糊、清冷。
- 剪映自己新建的草稿：只有加密的 `draft_content.json`，没有 `draft_info.json`。外面写好的明文草稿复制进草稿目录之后仍是明文，并且能打开。加密影响的是读取剪映自己的草稿，不影响我们生成。pyJianYingDraft 只新建、不读旧草稿，本 skill 不用任何解密。

## 草稿里要能直接改的

用 pyJianYingDraft 新建草稿，轨道按下面拆开：

- 口播主轨切成段，一段一个片段。常规变速和时长已能改。
- 每条空镜单独一条轨道，方便之后拖长度、改变速、换素材。这三下还没在剪映里拖过，待验证。
- 字幕是剪映文本段，关键词带颜色。不把字幕烤进画面。文本可改、分色还在，已验证。
- BGM、每一条音效、人声，各占一条音轨。音效分轨已看到。

素材路径写绝对路径。主文件只写 `draft_content.json`。

## 写不进剪映原生特效的

HTML 渲染的花字、盖章、数字滚动、打字机。每条单独导出一小段带 alpha 的片子，各放一条特效轨。剪映里透明的格式只有两种：ProRes 4444（`-c:v prores_ks -profile:v 4444 -alpha_bits 16`），或 PNG 序列。不要用 VP9 webm。

解 ProRes 4444 时，ffmpeg 7.1 给出的像素格式是 `yuva444p12le`（这次 Windows 上的完整版也是）。自检认 `yuva444p12le` 和 `yuva444p10le` 都算带 alpha，不要因为不是 10le 就判失败。编码参数仍可以写 `-pix_fmt yuva444p10le`。

剪辑师可以移动这些短片、改时长、改变速、删掉，或换成剪映自己的花字。改不了的只有动画内部。渲染参数在 `../SKILL.md` 第 8 步。按条导出，不要先叠成一条总叠加层。

## 字不要叠两层

某一句的字如果已经做成剪映文本，这条特效的叠加只渲染图形（圈、线、章的形状、光），不要再渲染同一句字。两套字会叠在一起。

手绘标记如果按估出来的剪映文字位置去摆，可能和剪映实际排出来的字对不齐。这种对位要人看，不能当成已经对齐。待验证。

## 响度

剪映没有总线限幅。离线按草稿重混的一条，真峰值测到 −0.7 dBTP，超过 −1 dBTP 的上限。剪映导出的 mp4 必须再测一遍真峰值（`ebur128=peak=true`）。超了就在剪映里把总音量降大约 0.5 dB，再导出复测，直到 ≤ −1 dBTP。

ffmpeg 合成、带限幅的成片不能代替这次测量。那条成片这次是 −14.0 LUFS、真峰值 −3.4 dBTP，只说明限幅那条过了。

## 草稿目录

`%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft` 在这次剪映 11.7 上就是草稿目录。仍以剪映「全局设置」里的草稿位置为准，写成配置项，不写死用户名。

## 已核实（上游仓库 GuanYixuan/pyJianYingDraft）

- 最新版 0.3.1（2026-10-14）。`DraftFolder.create_draft` 可直接新建草稿；生成的草稿要在 Windows 版剪映里导出。
- 上游在剪映 10.8 上验证过新建草稿的本地素材、轨道、文本/花字/文本动画、滤镜、转场、关键帧、贴纸、蒙版、音频、导入 SRT。
- 字体：未缓存的字体要打开两次草稿才显示正确。特效或动画资源未缓存时，打开可能提示加载失败。这次没再测字体缓存。
- 新草稿不在列表里：进出一个已有草稿，或重启剪映。这次复制进去的三份草稿被剪映登记并能打开；没复现「不在列表里」。
- 自动导出只支持 Windows + 剪映 6 及以下；7 以上由剪辑师手动导出。导出要有对应权限，否则可能卡死。剪映 11.7 里点导出，这次没测。
- 曲线变速暂不支持。脚本里速度用恒定值，观感不快于 1.5 倍（见 `pacing.md`）。口播段的常规变速在剪映里可以再改。

## 质检

不在 Codex 生成的草稿上做质检，也不必读草稿。等剪辑师从剪映导出成片后，用现有的 ffmpeg 和 Python 质检直接跑这个 mp4。复查哪些项见 `qc_checklist.md` 的「剪映导出后」。导出这一步还没做，待验证；真峰值那一条等有了导出文件就必须测。

## 建议流程

1. 剪辑师若要换成剪映自带花字，先把样式名填进 kw_class 的 `jianying` 字段。在能读模板之前，样式名由 Codex 写进新草稿，不复制他的草稿。
2. Codex 按 spec 新建草稿，只写 `draft_content.json`，素材用绝对路径：口播主轨分段，每条空镜独立轨道，剪映文本字幕（关键词上色），BGM、每条音效、人声分轨。
3. 每条 HTML 特效一段带 alpha 的短片（ProRes 4444 或 PNG 序列），各占一条特效轨。字已经在剪映文本里的，叠加只留图形。
4. 字在人后若剪辑师改用剪映「智能抠像」：把人像复制一层盖在大字上，抠像前后擦掉误抠物。
5. 剪辑师打开草稿（字体不对就再开一次），自己改时长、变速、换掉或删掉特效，然后手动导出。
6. Codex 对导出的 mp4 做质检，含真峰值。超了 −1 dBTP 就让剪辑师把总音量降大约 0.5 dB 再导一次。导出没跑通之前，同时交出保底包：成片 + SRT + 分镜表。
