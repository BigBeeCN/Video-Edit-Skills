# 剪映工程（pyJianYingDraft）

> 目标：交给剪辑师一份他自己能微调的剪映工程。他要能改特效、空镜时长和变速。整段要在他的 Windows 剪映上实测一次。实测前这一步标「待验证」，保底交付成片 + SRT + 分镜表（另外两张表见 `spec_schema.md`，每次都交）。

## 草稿里要能直接改的

用 pyJianYingDraft 新建草稿，轨道按下面拆开：

- 口播主轨切成段，一段一个片段。
- 每条空镜单独一条轨道。剪辑师可以拖长度、改变速、换成另一条素材。
- 字幕是剪映文本段，关键词带颜色。不把字幕烤进画面。
- BGM、每一条音效、人声，各占一条音轨。

## 工具

pyJianYingDraft 只能新建草稿，不能读已有草稿。新版剪映的草稿通常是加密的（维护者在 issue #82 提到 8.2.0 编辑后和新建的草稿会加密），不写具体从哪个版本开始。加密影响的是读取，不影响生成。读取已有草稿要自己传 `fallback_loader`，上游不提供解密，本 skill 不使用任何解密方案。所以只新建，不改剪辑师已经做好的草稿。

## 写不进剪映原生特效的

HTML 渲染的花字、盖章、数字滚动、打字机。每条单独导出一小段带 alpha 通道的片子，各放一条特效轨。剪辑师可以移动、改时长、改变速、删掉，或换成剪映自己的花字。改不了的只有动画内部。

这些短片仍用 HTML/Canvas + Playwright 逐帧渲染（参数在 `../SKILL.md` 第 8 步），按条编码，不要先叠成一条总叠加层，也不要先合成进画面。

## 待验证

必须在剪辑师的 Windows 剪映上测一次：

- (a) 主文件是 `draft_content.json` 还是 `draft_info.json`。上游写前者；有用户在 macOS 5.9 上要改名为后者。以这台机器上实际草稿文件夹里的文件名为准。
- (b) 剪映是否把 alpha 通道显示对。不行就改两条退路：导入 PNG 序列；或把这条特效合成进画面。合成进画面之后，这条就不能单独调时长和速度。
- (c) 素材路径必须是剪辑师这台机器上的 Windows 路径。换机器只改配置里的根目录，不写死。

另外：

- 常见的默认目录 `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft` 只是第三方说法。草稿目录以剪映「全局设置」里的草稿位置为准，做成配置项。
- SRT 仍作为保底文件交付。字幕进草稿走剪映文本段，不依赖 SRT 导入。若改用 SRT 导入，时间是否对齐仍要实测。

## 已核实（上游仓库 GuanYixuan/pyJianYingDraft）

- 最新版 0.3.1（2026-10-14）。`DraftFolder.create_draft` 可直接新建草稿；生成的草稿要在 Windows 版剪映里导出。
- 上游在剪映 10.8 上验证过新建草稿的本地素材、轨道、文本/花字/文本动画、滤镜、转场、关键帧、贴纸、蒙版、音频、导入 SRT。
- 字体：未缓存的字体要打开两次草稿才显示正确。特效或动画资源未缓存时，打开可能提示加载失败。
- 新草稿不在列表里：进出一个已有草稿，或重启剪映。
- 自动导出只支持 Windows + 剪映 6 及以下；7 以上由剪辑师手动导出。导出要有对应权限，否则可能卡死。
- 曲线变速暂不支持。脚本里速度用恒定值，观感不快于 1.5 倍（见 `pacing.md`）。剪辑师在剪映里可以自己再改变速。

## 质检

不在 Codex 生成的草稿上做质检，也不必读草稿。等剪辑师从剪映导出成片后，用现有的 ffmpeg 和 Python 质检直接跑这个 mp4。复查哪些项见 `qc_checklist.md` 的「剪映导出后」。

## 建议流程

1. 剪辑师若要换成剪映自带花字，先把样式名填进 kw_class 的 `jianying` 字段。在能读模板之前，样式名由 Codex 写进新草稿，不复制他的草稿。
2. Codex 按 spec 新建草稿：口播主轨分段，每条空镜独立轨道，剪映文本字幕（关键词上色），BGM、每条音效、人声分轨，每条 HTML 特效一段带 alpha 的短片、各占一条特效轨。
3. 字在人后若剪辑师改用剪映「智能抠像」：把人像复制一层盖在大字上，抠像前后擦掉误抠物。
4. 剪辑师打开草稿（字体不对就再开一次），自己改时长、变速、换掉或删掉特效，然后手动导出。
5. Codex 对导出的 mp4 做质检。实测通过前，同时交出保底包：成片 + SRT + 分镜表。重要程度表和时长统计表每次都交。
